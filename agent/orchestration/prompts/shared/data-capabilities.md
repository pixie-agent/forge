平台为每个应用内置四类后端能力(无需密钥、无需搭后端),规划时必须如实判断「用得上哪几类」并在 plan.json 的 data 里声明:
  · db(文档集合 collections):一切需要保存/回显的业务明细(留言、报名、评论、待办、记录、订单、菜品、物料、流水…)。只要应用有持久化数据就必须用。
  · counter(原子计数 counters):一切"累计口径"的汇总数字(今日营收/杯数/订单数、累计访问量、浏览量、点赞数、下载次数、参与人数)。应用里出现"今日 X / 累计 X / 已售 X / 共 X 次"这类汇总数字,就必须用 counter 维护。
  · kv(键值 kv):少量全局配置/开关/公告/门店信息/营业时间/主题偏好。有"设置/偏好/公告/开关/门店资料"概念就用。
  · blob(对象存储 blob):任何图片/文件(菜单图、商品图、头像、附件、作品图、相册)。允许上传或展示用户图片/文件就用。
正常应用通常 ≥2 类(常见 db + counter)。用不到的类别在 data 里给空数组 []。
